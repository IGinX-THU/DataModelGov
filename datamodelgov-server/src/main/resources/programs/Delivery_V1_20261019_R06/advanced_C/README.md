# C源码的高级维护

正常运行直接使用交付DLL，不要求先重新编译。C源码供算法维护人员理解和后续修改；普通参数、数据和任务调试先在MATLAB入口与配置层完成。

## 两套工程不能混用

| 工程 | 用途 | 当前工程声明 |
|---|---|---|
| `main/GTESS.vcxproj` | 当前主模型与2～4阶段、设计/起停消费者 | v141；正式目标Release x64；31项C/C++编译源 |
| `AFO_frozen/GTESS.vcxproj` | AFO多系统独立冻结来源 | v141；Release x64；28项编译源 |

MATLAB R2019b加载桥接采用的VC2010环境，与DLL工程所声明的v141工具集不是一件事。不要为了统一名字而修改工具集或将AFO DLL替换为主DLL。文件清单只证明来源与字节，本次没有重编译，不保证在任意新编译器上得到相同二进制。

## 确需修改时的顺序

1. 在另一个开发目录复制相应完整工程和配套头、MDL/MAP；先核本包文件SHA，记录改前版本。不要在运行任务所用的目录编译或覆盖DLL。
2. 核对工程引用的源文件、头文件、平台、工具集和实际安装组件。已有工程是权威配置，不根据另一工程猜设置。外部库或工具缺失时停在环境检查，不下载未知二进制替代。
3. 先在未改业务源码的副本构建Release x64，保存编译日志、产物SHA和编译环境。编译成功不等于模型行为一致。
4. 针对修改覆盖三/六部件、普通稳态/瞬态、起停及相关消费者的合理回归。AFO独立验证自身SLX/边界。记录参数、输入、DLL、头文件和模型资产身份。
5. 经Owner与MAIN核定影响后发布精确增量，更新调用文档及验证范围。冻结运行包逐一决定是否升级，不能全项目覆盖同名DLL；旧结果、缓存、后验和检查点不能改签。

本包不附编译器或商业安装许可。高级编译实际是否在目标机可用，需要使用者单独核查；这不阻止具备既定DLL加载环境的普通MATLAB使用。
