## 5 发现的问题及修复

1. 首次静态启动因中文路径直接进入MATLAB命令行而变成问号，尚未执行测试或DLL。启动方式改为ASCII命令调用同目录CP936引导脚本后通过。
2. 首次综合批的保存重试失败：R2019b默认CP936读取UTF-8 JSON，中文Windows路径中部分字节与反斜杠组合导致解析错误。程序改为显式、严格的UTF-8读取并统一用于状态、字典、流和命令入口，保存重试补测通过。
3. 准备过程中会话状态曾早于catalogHash计算完成而可见。现在在完整准备成功后一次性赋予会话对象，避免外部读到半准备状态；实际补测无该错误。
4. 原QA将TEMP置于当前工作目录之下，引发Simulink恢复默认CacheFolder时的目录冲突警告。仅调整QA目录布局为同级，实际恢复检查通过；历史警告不删除。该修复不修改物理模型。

旧失败、警告和超时标记全部保留。最终适用短测没有仍未解决的失败项；未覆盖项在下一节列出，不等同于通过。

## 7 保留限制

- 本轮只实现和验证后台适配，不开发GUI。实际曲线约5Hz刷新、200ms操作反馈、分页缩放、图例联动和图元数量仍需界面团队验证；预制流通过不能证明绘图内存稳定。
- 物理回归为短历程，没有重跑30秒全工况、长包线、一小时物理模型、全部Np挡位或全部故障；不能将短测外推为完整物理验证。
- 仍从配套正转速状态准备，不包含起动停车或任意工况自动配平；双桨是既有等效负载，不是旋翼传动动力学。
- 燃油代理仅展示，不改变发动机实际供油支路。
- 空气温压是保护前供气总状态，不是支路出口温压；现有空气选择器未连接输入10和多路共源关系不作物理修复。
- 滑油oil16_01单位未确认，显式标记而不转换。
- 未覆盖进程崩溃后恢复数值状态、系统硬盘满、网络盘原子发布、真实隔离机/目标GUI、硬实时操纵性能。
- 本次不重新验证其他阶段算法；R065没有R07的TC27增量。顶层旧Word/HTML保持R06原字节，新接口以R065补充说明为准。
